# COSMOS

**Local-first experimental cognitive runtime and Davis Cosmic Synapse Theory (CST) engineering toolkit.**

COSMOS is an open research/software project by **Cory Shane Davis** for studying compact dynamic internal state, durable memory, Hebbian-style associations, local model orchestration, evidence/provenance, sensory summaries, background maintenance loops, and browser/creative systems.

> **Scientific boundary:** the repository distinguishes implementation, observation, measurement, null results, hypotheses, and metaphor. Persistence or autonomy is not evidence of consciousness. Quantum provenance is not the same claim as quantum performance advantage.

## Why this repository was rebuilt

The 2026 professionalization pass removed an unrelated Farnsworth package, foreign package/license metadata, generated bytecode/build outputs, tracked `node_modules`, local logs, scanner outputs, and private runtime archives. The previous tree is preserved at `backup/pre-cosmos-cleanup-2026-08-12` and in Git history.

The current `cosmos/` package is source-first: readable `.py` files replace the prior compiled-bytecode-only public tree.

## Working core

The dependency-free Python core includes:

- **Dyn12 state** — 12-scalar recurrent control state with calibrated Gaussian state-affinity kernel and preflight checks.
- **Persistent memory** — SQLite durability, deterministic local retrieval baseline, and Hebbian-style concept association weights.
- **COSMOS Runtime** — closes the loop across memory, state, optional sensory summary, response backend, persistence, and evidence.
- **Local Ollama adapter** — opt-in localhost inference; no cloud fallback.
- **Evidence ledger** — append-only JSONL with SHA-256 hash chaining and explicit evidence statuses.
- **Reality Bridge baselines** — deterministic prediction receipts, persistence/moving-average baselines, and seeded lottery random baseline.
- **Quantum provenance primitives** — labeled record validation and deterministic seed derivation; no claim of quantum ML advantage.
- **Heartbeat** — fail-soft scheduled maintenance jobs.
- **Local JSON API** — stdlib HTTP server with `/health`, `/state`, `/chat`, and `/sensory`.
- **CLI** — `info`, `doctor`, `demo`, `chat`, `web`, `evidence-verify`, and `state-preflight`.

## Quick start

```bash
git clone https://github.com/NavisWORLD/Cosmos.git
cd Cosmos
python -m venv .venv
```

Windows:

```bat
.venv\Scripts\activate
python -m pip install -U pip
pip install -e ".[dev]"
pytest
python -m cosmos demo
```

macOS/Linux:

```bash
source .venv/bin/activate
python -m pip install -U pip
pip install -e '.[dev]'
pytest
python -m cosmos demo
```

## Use a local language model

COSMOS defaults to the dependency-free `echo` backend so installation and tests never require a model server.

For Ollama:

```bash
export COSMOS_BACKEND=ollama
export COSMOS_OLLAMA_MODEL=qwen2.5:1.5b
python -m cosmos doctor
python -m cosmos chat
```

On Windows PowerShell:

```powershell
$env:COSMOS_BACKEND="ollama"
$env:COSMOS_OLLAMA_MODEL="qwen2.5:1.5b"
python -m cosmos chat
```

## Local API

```bash
python -m cosmos web --host 127.0.0.1 --port 8081
```

Then:

```bash
curl http://127.0.0.1:8081/health
curl http://127.0.0.1:8081/state
curl -X POST http://127.0.0.1:8081/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"hello cosmos"}'
```

Sensory integration uses compact numeric summaries:

```bash
curl -X POST http://127.0.0.1:8081/sensory \
  -H 'Content-Type: application/json' \
  -d '{"packet":{"audio_energy":0.22,"motion":0.04}}'
```

The core does **not** store raw camera/audio by default.
