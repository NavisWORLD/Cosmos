# CNS Runtime & Loops Manual

COSMOS is best understood as a runtime composed of loops at different timescales.

## Conversation loop
Receive → clean/classify/route → interaction lock/state → retrieve memory → read fresh sensory summary → provenance/state packet → update dynamic state → local synthesis → return → persist → release.

## Sensory loop
`mic/camera/device bridge → local features → compact summary → freshness gate → runtime/research logger`

Prefer summaries and discard raw media unless explicitly retained.

## Persistence loop
Turn text can update durable history, semantic index, Hebbian associations, salience, teacher/lesson ledgers, timestamps, and hashes.

## Heartbeat loop
A scheduler checks due maintenance tasks. Optional maintenance must fail soft.

## Quantum loop
Provider/backend/hardware-vs-simulator labels are mandatory. Archive replay aids reproducibility; performance claims require matched classical controls.

## Paired-state research loop
Join internal/sensory state to text by actual timestamps, then compare aligned, shuffled, shifted, and no-conditioning conditions.

## Growth loop
Warm-start lineage is compatible with continual growth, but controlled benchmarks need frozen named corpus snapshots.

## Service topology
Documented/local lineages have used 8081/8090 web paths, 8765 sensory API, 11434 Ollama, 11435 helper bridge, and 11500/11501 model/native bridges. Probe process ownership before stop/restart.
